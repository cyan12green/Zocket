# Milestone 3 (proposal): HTTP/1.1 request parsing + response layer

**Status**: done (superseded by Milestone 4, which replaced the hardcoded
handler with the config-driven phase pipeline; see `docs/M4.md`). Parser,
response builder, reactor integration with `--http`/`--echo` modes, e2e checks
and benchmarks all complete.

**Goal**: turn the raw echo reactor into an HTTP server — parse request line +
headers, serve keep-alive HTTP responses — while keeping the raw-echo modes
runnable so M2 benchmarks stay reproducible. M3 ends when `bombardier`
produces *valid* HTTP metrics (this kills the biggest caveat in
`bench/BENCH.md`).

## Tasks

1. **`src/http/parser.zig`** — incremental state-machine parser over
   `net.Buffer` (never blocks, handles partial reads):
   - request line: method, request-target, HTTP-version (accept `HTTP/1.1`;
     tolerate `HTTP/1.0`)
   - headers: `Name: value` pairs into a fixed table; `\r\n` line endings
     (lone `\n` tolerated); CRLF-only
   - body: `Content-Length` (no chunked in M3 — documented non-goal)
   - keep-alive: HTTP/1.1 keep-alive by default; honor `Connection: close`
   - limits: 8 KB per-line cap → `431 Request Header Fields Too Large`;
     malformed line → `400`
   - unit tests: feed byte-by-byte / in chunks, pipelined multi-request
     buffers, header edge cases (no space, multiple `Host:`, empty header
     name), keep-alive detection, error cases
2. **`src/http/response.zig`** — minimal response builder:
   - status line + headers + body, `Content-Length` always set; statuses:
     `200`, `400`, `431`, `501`
   - `writev`-based flush so headers+body go out in one syscall batch
   - tests: byte-exact expected wire output, length correctness
3. **Reactor integration** (`src/net/reactor.zig`):
   - per-connection state: `parser` + `response_pending`; read → parse →
     respond; after flush, keep parsing the same buffer (pipelining-safe)
   - keep-alive payoff: one accept/dispatch serves N requests → dispatch cost
     amortizes
   - semantics: respond `200 OK` with the request body echoed as the response
     body (keeps echo DNA, diffable against raw-echo numbers); `GET /` returns
     the body echo
   - keep `--single`/`--threads` flags; add `--echo` (raw, today's behavior)
     and `--http` (new) modes so M2 baselines stay bit-reproducible
4. **End-to-end tests**: python `http.client` keep-alive loop (10 requests, 1
   connection, all 200 + body match), curl smoke, `400`/`431` error paths, and
   a reactor integration test with HTTP traffic.
5. **Benchmarks** (re-run harness):
   - bombardier sweep: now valid HTTP metrics — real req/s + latency
     percentiles for `single` and `multi_threaded_4`
   - custom echo client still covers raw-echo modes; add `bench/bench3.sh`
     for HTTP sweeps
   - keep-alive concurrency sweep: 1, 10, 100, 1000 connections
6. **Docs**: update `bench/BENCH.md` (drop/rewrite the parse-error caveat, add
   M3 tables), `AGENTS.md` (`src/http/` module, new flags, test-collection
   note), `README.md` milestone check.

## Expected improvements (honest framing)

- **Measurable win**: valid HTTP benchmark numbers — M2's only benchmark
  weakness disappears; keep-alive amortizes dispatch (1 wakeup per connection
  instead of per request).
- **Throughput**: parsing is pure userspace, adds no syscalls to the
  per-request path → expect no regression vs raw echo; MT-4 should keep
  ~+25–60% over single-threaded under the new protocol.
- **Latency floor**: response written in one `writev` batch (vs today's
  read→echo→modify→write two-epoll-round-trip) → expect lower p50 at low
  concurrency.
- **Foundation**: parser output is the exact input M4's router/DSL needs.

## Explicit non-goals for M3

Chunked transfer-encoding, gzip, 100-continue, keep-alive timeout/idle
reaping (defer to M3.5 with a timer wheel), HTTP/2, full RFC 7230 compliance,
URL decoding.

## Verification gates

`zig build test` green at each step; `zig build run -- --http` + curl
end-to-end; M3 benchmark tables recorded and committed; M2 raw-echo numbers
still reproducible via `--echo`.
