# Milestone 4: config-driven phase pipeline

**Status**: done. The M3 hardcoded HTTP response path is replaced by a
config-driven, phase-based request pipeline. `zig build test` green (69 tests:
36 M3 + 33 new). Same-day A/B shows <5% overhead (see `bench/BENCH.md`).

**Goal**: turn the M3 HTTP handler into a module registry + phase pipeline, so
future modules (auth, headers, static files, ...) attach to named phases from
configuration instead of being hardcoded in the reactor.

## What was built

- `src/dsl/phase.zig` — the 10 nginx-style phases, in execution order:
  `post_read`, `server_rewrite`, `find_config`, `rewrite`, `post_rewrite`,
  `preaccess`, `access`, `post_access`, `content`, `log`. Names follow nginx;
  internal behavior is ours.
- `src/dsl/router.zig` — routes (`path` + `exact`/`prefix` match + per-phase
  module bindings). Exact beats prefix; longest prefix wins.
- `src/dsl/registry.zig` — the comptime module registry. A module is a
  comptime `Module` value (`name`, `phase`, `run`). Modules self-register by
  exporting one; the registry enumerates them and dispatches a runtime config
  name to a run function via a comptime-unrolled lookup. No dynamic loading.
  Also defines the per-request `Context` (mutable `Request`/`Response`
  pointers, matched route, `close_after_write`).
- `src/dsl/pipeline.zig` — the phase dispatch loop. `find_config` runs the
  route matcher and records the match; every phase then dispatches the module
  the matched route binds to that phase, in order. A module returns `pass`,
  `handled` (response ready — chain stops), or `short_circuit` (chain stops,
  caller sends the default). Chain ends without a claim → caller sends the
  default 404.
- `src/dsl/modules/echo.zig` — the `echo` content module: `200 OK` echoing the
  request body, `413` for bodies above the send-buffer cap, byte-identical to
  the M3 hardcoded handler.
- `src/runtime/config.zig` — `Config` (route table). Source is either a
  comptime struct literal (`Config.default()` = echo on `/`) or a JSON file:
  `Config.fromJson` parses with `std.json` (runtime), validates module names
  and duplicate phase bindings against the registry.
- `src/runtime/server.zig` — the shared, immutable `Server` the reactors call:
  `handleRequest` = `pipeline.run(registry, cfg.routes, ctx)`.

### JSON config at comptime: what the pinned snapshot allows

`@embedFile` + `std.json.parseFromSlice` at **comptime** was attempted first and
does not compile in this snapshot: `std.json` needs a runtime allocator, and its
first allocation goes through `@intFromPtr` (`std.mem.zig:4257`), which is
runtime-only — "unable to evaluate comptime expression". So, per the milestone
fallback, the config is either a **comptime Zig struct literal**
(`Config.default()`, zero-cost, no file dependency) or a **JSON file parsed at
startup** with `std.json` (runtime path taken from `--config`). Both produce the
same `Config` value; the pipeline and registry are identical either way. A
sample file is `config.example.json`.

## How it is wired

`net/reactor.zig` no longer builds responses itself. In `.complete`, it creates
a `Context{ .req, .resp }`, calls the shared `runtime.Server` through the phase
pipeline, then writes whatever response the pipeline produced (adding the
`Connection` header from keep-alive + `ctx.close_after_write`). `not_handled`
→ default 404. Parse errors (400/431/501) are unchanged. `--echo` and `--single`
modes never touch the pipeline.

`--http` uses `Config.default()` unless `--config <file>` is given. New flag:

    zig build run -- --config config.example.json
    zig build run -- --http --config /path/to/routes.json   # both spellings

## What a config looks like

```json
{
  "routes": [
    { "path": "/echo", "match": "exact",  "modules": { "content": "echo" } },
    { "path": "/",     "match": "prefix", "modules": { "content": "echo" } }
  ]
}
```

`modules` maps a phase name to a registered module name. Unknown module names
and duplicate phase bindings are rejected by `Config.validate`.

## Out of scope (still TODO, later sessions)
